# 选择题与 FSRS 评级的映射说明（RAY-293 交付文档）

> 评审依据文档。结论先行：**选择题只是答题形式，不是第二套记忆体系。**

## 1. 一句话结论

选择题与卡片模式**共用同一条 FSRS-7 调度曲线与同一套复习记录**。
选择题的「答对 / 答错」只是把 FSRS 的两个评级档位（Good / Again）换了一种
采集入口，不引入任何新的调度参数、状态字段或评分口径。

## 2. 映射表

| 选择题结果  | FSRS 评级 | 用户语义（三档评分体系） | 说明                                           |
| ----------- | --------- | ------------------------ | ---------------------------------------------- |
| 答对        | `good`    | 认识                     | 与卡片模式点「认识」完全等价                   |
| 答错        | `again`   | 不认识                   | 与卡片模式点「不认识」完全等价                 |
| —（不出现） | `hard`    | 模糊                     | 二元对错没有中间态，选择题不出 `hard`          |
| —（不出现） | `easy`    | —                        | 选择题不自动标熟；「标熟」只在卡片模式显式操作 |

「评分档位」设置（三档 / 四档）只影响卡片模式的按钮入口与键盘映射，
与选择题无关——选择题永远只产生 `good` / `again` 两档。

## 3. 共用调度曲线与复习记录

答题后走与卡片模式**完全相同**的落库路径：

```
useMultipleChoiceSession.select
  → provider.grade(card, rating, context)          // rating ∈ {good, again}
  → @lexilexi/core gradeReview(db, input)
  → new Scheduler(memoryFieldsToCardInput(previous.fields), now).review(input.rating)
  → 同一 Dexie 事务内原子写入：review 事件 + 新 MemoryState
```

- **同一张 MemoryState**：`stabilityDays` / `difficulty` / `reps` / `lapses` /
  `due` / `lastRating` 等字段由同一个调度器更新，与答题形式无关。
  卡片模式答「认识」和选择题答对，落在同一个词条上是**同一条**学习曲线。
- **同一事件流**：复习事件（时间戳、评级、对错）记录在本地 IndexedDB
  的 `events` 表，`rating` 字段为 `good` / `again`，与卡片模式的事件
  不可区分（除 `exerciseType` 标注，见下）。
- **撤销同通道**：选择题的评分也返回撤销证据（事件 id + 评分前状态），
  走与卡片模式相同的 `undoGrade` 单步撤销。
- **队列同口径**：选择题队列就是卡片队列（`loadQueue` 同一
  `getStudyQueueItemIds` 路径），只是每张卡附带一道题。

### 事件标注字段（不参与调度）

选择题落库时在 review 事件上标注：

| 字段               | 值                  | 是否影响调度                                                    |
| ------------------ | ------------------- | --------------------------------------------------------------- |
| `exerciseType`     | `"multiple-choice"` | 否——仅标注答题形式，调度器不读取                                |
| `answerWasCorrect` | 答对 / 答错         | 否——仅记录对错事实供统计回溯                                    |
| `reviewDurationMs` | `0`                 | 否——选择题不精确计时（会话内自动判分，时长无意义；S2 迭代再议） |

`gradeReview` 内部只把 `input.rating` 传给 `Scheduler.review()`，
`exerciseType` / `answerWasCorrect` / `reviewDurationMs` 均不进入
FSRS 计算。这一点与官方参考实现口径一致（`@lexilexi/fsrs`，
`fsrs-verify` 对照用例覆盖），选择题没有改动任何调度代码路径。

## 4. 混淆项来源（隐私红线）

混淆项只来自**本机数据**（`packages/core/src/distractors.ts`）：

1. **历史常错词**——本机记忆状态中 `lapses > 0` 的条目；
2. **形近词**——本机词库内与目标词条编辑距离 ≤ 3 的条目；
3. 不足时以本机词库**随机回退**补齐。

**同义词条剔除**（RAY-293 后续修复，Jack 裁定「剔除」方案）：与目标词
同义的词条不进三级回退池——同义选项「语义上也说得通」被判错属质量缺口。
剔除为双向口径（目标词的 `Sense.synonyms` 命中的词条、或自身 `synonyms`
含目标词的词条），作用于常错词 / 形近词 / 随机三级来源，**英译中与
中译英两个方向一致**；不采用「同义判对」（同义/近义边界模糊，判对口径会
把「相近但不完全同义」的词放行，稀释记忆精度）。此剔除只影响出题呈现，
不改变任何评分与调度语义。

**级联回退 + 保底填充**（RAY-293 修正决策，撤回「候选不足跳题」）：三级
回退凑不够 `MIN_QUIZ_OPTION_COUNT`（4）时，从词库剩余词条随机补充——仅
排除目标词本身、不再剔除同义词条，确保每个词都能被出题（「宁可题目简单，
不可永远不学」，用户至少见到这个词、走一遍 FSRS 调度）。仅当词库小到连
保底填充都凑不够（或没有任何正确项——无释义义项）时该题才跳过、不产生
任何 review 事件；常规词库规模下不会触发。

**无任何跨用户数据、无联网请求、无埋点上报。**

## 5. 中译英方向的映射（RAY-293 新增）

「选择题出题方向」设置三档（英译中 / 中译英 / 混合）只改变**题目呈现**：

|                | 题面               | 选项             |
| -------------- | ------------------ | ---------------- |
| 英译中（默认） | 词条原文（+ 词性） | 主释义（中文）   |
| 中译英         | 主释义（中文）     | 词条原文（英文） |
| 混合           | 逐题随机二选一     | 随方向而定       |

方向记录在题目的 `direction` 字段，**不进入评分与调度**：中译英答对同样
落 `good`、答错同样落 `again`，与英译中在记忆系统里零差别。混淆项来源
口径（含同义词条剔除）两方向完全一致，仅选项文本从「主释义」换成
「词条原文」（`generateTermOptions` 与 `generateOptions` 共用同一生成管线）。

## 6. 结论

- 选择题与卡片模式是**两个入口、一条曲线、一套记录**。
- 答对 = 认识（Good），答错 = 不认识（Again），各自走官方 FSRS-7 对应分支。
- 切换出题方向（含中译英）不改变任何记忆系统语义。
